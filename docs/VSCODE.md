# Debugging in VS Code with SweetPad

This project is set up to build, run, and debug in **VS Code** (or Cursor) on
macOS using the [SweetPad](https://sweetpad.hyzyla.dev) extension, which drives
`xcodebuild` under the hood. The Xcode project is generated by XcodeGen, so the
editor config lives in source (`project.yml`, `.vscode/`) and the `.xcodeproj`
is disposable.

## One-time setup

### 1. Point the command line at Xcode (required)

The active developer directory on this machine is the Command Line Tools, but
SweetPad needs the full Xcode toolchain. Switch it once:

```bash
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
xcodebuild -version   # should print an Xcode version, not an error
```

(If you ever see an `IDESimulatorFoundation` plugin error, run
`sudo xcodebuild -runFirstLaunch` once.)

### 2. Install the command-line tools (already installed here)

```bash
brew install xcodegen xcode-build-server xcbeautify swiftformat
```

- **xcodegen** – generates `DamageTracker.xcodeproj` from `project.yml`
- **xcode-build-server** – feeds SourceKit-LSP for autocomplete / jump-to-def
- **xcbeautify** – prettifies SweetPad's build output (optional)
- **swiftformat** – formatting (optional)

### 3. Install the VS Code extensions

Open this folder in VS Code and accept the recommended extensions prompt, or
install manually:

- **SweetPad** (`sweetpad.sweetpad`) – build/run/debug
- **CodeLLDB** (`vadimcn.vscode-lldb`) – the debugger SweetPad attaches with

(These are listed in `.vscode/extensions.json`.)

### 4. Generate the project + LSP config

```bash
./scripts/bootstrap-vscode.sh
```

This runs `xcodegen generate` and writes `buildServer.json`. Re-run it any time
you edit `project.yml` or add/remove Swift files.

## Daily use

1. Open the **SweetPad** panel in the VS Code sidebar.
2. Under **Build**, pick the `DamageTracker` scheme and a simulator (or device).
3. Press **▶︎** to build & run.

### Debugging with breakpoints

1. Set breakpoints in the gutter.
2. Open **Run and Debug** (⇧⌘D) and choose **"Debug DamageTracker (SweetPad)"**,
   then press **F5**.
3. The `sweetpad: launch` pre-launch task builds and launches the app, and
   CodeLLDB attaches automatically.

The debug/build tasks are defined in `.vscode/launch.json` and
`.vscode/tasks.json`.

## What's committed vs. generated

| Path | Committed? | Notes |
|---|---|---|
| `project.yml`, `.vscode/`, `scripts/` | ✅ | Source of truth |
| `DamageTracker.xcodeproj/` | ❌ (gitignored) | `xcodegen generate` |
| `buildServer.json` | ❌ (gitignored) | machine-specific paths; `bootstrap-vscode.sh` |
| `build/`, `DerivedData/`, `.sweetpad/` | ❌ (gitignored) | build artifacts |

## Troubleshooting

**`The "path" argument must be of type string. Received undefined`** (in any
SweetPad command). SweetPad couldn't auto-detect the Xcode workspace. This is an
XcodeGen project, so there's no standalone `.xcworkspace` — only the one embedded
in the generated `.xcodeproj`, which SweetPad's scan misses. `.vscode/settings.json`
already pins it:

```json
"sweetpad.build.xcodeWorkspacePath": "DamageTracker.xcodeproj/project.xcworkspace"
```

Reload the VS Code window after the first checkout so SweetPad picks it up.

**`tool 'xcodebuild' requires Xcode`** — the active developer dir is still the
Command Line Tools. Run the `sudo xcode-select -s …` command from step 1.

## Notes

- The shared scheme `DamageTracker` is defined in `project.yml` (under
  `schemes:`) so `xcodebuild -list` and SweetPad always find it.
- Autocomplete is most accurate after one successful build (it populates the
  DerivedData index that `buildServer.json` points to).
- You can still open `DamageTracker.xcodeproj` in Xcode normally; the two
  workflows coexist.
